Four case studies, simulated live. Foam pressed on a chrome bar, a cable laid into clips, a towel folded over, a protective film peeled off a phone. Each runs on its own GPU on this server, and these are not recordings: further down, every one is embedded live, and you can take the robot's hand.

TL;DR

Robot Sim Studio (RSS) is a toolkit for building interactive physics simulations of robot manipulation on Newton, GPU physics on Warp and CUDA. Rigid parts, cables, cloth and foam share one scene, each on a solver named in data, and anything in it can be grabbed and dragged in a browser while it runs. A live page rebuilds a scene file on every save, so a coding agent can turn a photo or a clip of a real bench into a simulated twin, one save at a time.

What RSS is

You put things in a place and step it: rss.Scene, scene.add(spec), scene.build(), sim.run(). RSS is also the import name: import robosimstudio as rss.

One way in

There is exactly one way to add something, Scene.add(spec). A new kind, solver or coupler registers from outside the library.

Physics stated as data

An asset says what it is; an arrangement says which backend serves each domain and how islands couple. What was built is recorded in a manifest.

Several engines, one interface

Newton's solvers (MuJoCo, VBD, XPBD, Featherstone, kinematic) and host engines co-simulated beside them (SuperDex, Genesis), pose in and wrench out.

An interactive studio

In the browser: click anything and drag it, drive each arm by a 6-DOF gizmo, tune deformable materials live, record takes and export them.

Agent-driven real-to-sim

A live page rebuilds scene.py on every save, and ./ctl snapshot --beside shows the scene next to the real reference.

Tasks as documents

A task is a .task file in an extended BDDL that lowers to a TaskSpec; Python can build the same object.

How it works

Every layer reads the same specs, from the scene you declare to the frames you render.

01 · Declare

Specs

Frozen dataclasses, written through constructors (rss.box, rss.sheet, rss.rod, rss.sponge, rss.robot) or a .task document.

02 · Arrange

Physics

An arrangement names a backend per domain, a coupler (proxy, admm or one_way), a collision policy and rates.

03 · Compose

Islands

Interaction graph, islands, channels, contact routing, solver, schedule, manifest. Host engines are split out and fed mirrored poses.

04 · Step

One schedule

One substep schedule over the composed solver, captured into a CUDA graph on Newton and Warp.

05 · Watch

View and render

The studio in a browser; GL, path-traced RTX, pyrender or offline mp4. A path-traced re-render replays recorded state, and nothing is re-simulated.

06 · Drive

Policies and data

An environment driven by a scripted routine, a graph policy or a VLA over a socket; episodes, video and LeRobot export.

User manual

The essentials, from the RoboSimStudio repository's README and docs. RSS is work in progress, and its code is not public yet.

Requirements

An NVIDIA GPU with a driver new enough for the CUDA runtime that Warp ships, and uv. Optional extras: [studio] (the browser studio), [bench] (tasks and policies), [rtx] (the path tracer) and [superdex] (Python 3.12).

Install and open a first scene

git clone https://github.com/KeplerC/robosimstudio.git
cd robosimstudio
uv run -m examples.scenes.rigid                            # two arms and three shapes; click and drag any of them
uv run python scripts/studio.py --task tool_sort/level2_1  # the studio on a task
Each prints a share URL; --no-share keeps it local. The first run builds the environment (about a minute), then Warp's kernel cache.

Put things in a place and step it

import robosimstudio as rss

scene = rss.Scene(cell="bench_075")
cube  = scene.add(rss.box(name="cube", half=(0.025,) * 3, at=(0, 0, 0.2)))
scene.add(rss.robot("panda"))

sim = scene.build()
sim.run(150).sync()
print(cube.position)        # (0.600, 0.000, 0.775) -- 25 mm above a 750 mm bench
rss.view(sim)               # ...and drive it in a browser
Swap rss.box for rss.rod, rss.sheet or rss.sponge and you have a rope, a towel, or a block of FEM foam co-simulated by SuperDex.

Write a scene

Constructors build the specs: rss.sheet(name=, size=, cells=, at=, material=), rss.rod(...), rss.RodSpec(nodes=…), rss.SoftSpec(asset=…), rss.sponge(...), rss.robot("panda", at=, arm=, gripper=). Poses are in the cell's work-surface frame. Change the physics with scene.with_physics(substeps=4). Nine runnable examples, in reading order: rigid, cable, cloth, cables, engines, sponge, genesis_cloth, ported, custom.

Write a task

(define (problem PICK_UP_THE_HAMMER)
  (:language pick up the hammer and place it in bin2)
  (:staging
    (:scene bench_075)
    (:embodiment panda)
    (:control-mode joint_position)
    (:episodes (:count 1) (:seed 0) (:sampler fixed))
    (:max-steps 2400)
  )
  (:objects hammer_0 - hammer)
  (:regions
    (bin2_hammer_region (:target bin2) (:ranges ((-0.195 -0.245 0.0 0.0))))
  )
  (:init)
  (:goal (In hammer_0 bin2_hammer_region))
)
Build it with uv run python scripts/bench_smoke.py --task <suite>/<variant>, run it with scripts/bench_run.py --task <suite>/<variant> --solve graph --capture-state, and list tasks with --list.

From real to sim, with an agent

Start the live page, then point a coding agent at it. The procedure lives in the repository (AGENTS.md and the real-to-sim skill), not in the prompt.

cd examples/live
./ctl up                                  # the page; prints http://localhost:8080 (--share adds a public URL)
claude --permission-mode acceptEdits      # or: codex -a on-request -s workspace-write
The agent then uses ./ctl status, ./ctl snapshot --camera <name> --beside ref/<photo>, ./ctl catalog robots cells, ./ctl eval "sim['<name>'].position" and ./ctl run N. A rebuild takes about 6 s, and the swap into the page under 0.1 s.
01

Read the reference

The surface, the robot, each object, the camera.

02

One thing per save

Cell, robot, objects, camera; after each save, status and snapshot --beside.

03

Act

./ctl run 120, or a generator through eval.

04

Stop

When the pair agrees, or say which number the reference cannot settle.
